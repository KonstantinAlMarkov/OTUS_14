= Эпик 2-2: Подготовить мобильное приложение под вывод нового продукта

**Статус:** В аналитике +
**Приоритет:** Критический (Highest) +
**Сложность:** 5 Story Points +
**Базовый срок реализации:** 2 недели (Спринт №2 и Спринт №3 ИТ-контура) +
**Ответственный:** Продукт оунер

---

== 1. Бизнес-контекст и цели

Внедрение нового продукта в меню сети закусочных требует обеспечения возможности его удаленного заказа, оплаты и доставки клиентами через интерфейс официального мобильного приложения.

=== Ключевые цели:
* Предоставить клиентам всех рас доступ к актуальной информации о новинке (название, состав, ингредиенты, КБЖУ, цена).
* Обеспечить сквозной процесс оформления онлайн-заказа, проведения оплаты и автоматической отправки события в систему управления заказами (OMS).
* Поддержать мультикультурный UI/UX для исключения барьеров при заказе инопланетными существами.

---

== 2. Поток данных и архитектурная интеграция (EDA/SOA)

Мобильное приложение взаимодействует с центральным бэк-офисом асинхронно через шину событий.

. Приложение вычитывает обновленные справочники меню из локального брокера планеты (`Planetary Kafka Broker`), куда данные зеркалируются с Земли.
. Приложение отображает новинку клиенту, используя динамические JSON-схемы расовых UI-паков.
. При совершении покупки приложение отправляет запрос на оплату. После успешного эквайринга в шину публикуется событие `Order_Paid`, которое слушают системы OMS и WMS.

---

== 3. Декомпозиция подзадач в Jira (Компонентный конвейер)

Реализация эпика в ИТ-контуре Kanban-доски жестко разделена на три обязательные подзадачи:

*Задача системной аналитики (SA-2.2)*::
Проектирование схемы маппинга JSONB для новых полей расовых интерфейсов. Разработка технических спецификаций дешифрации полей FLE (цена) на клиенте. Трассировка API-взаимодействия со смежными системами.

*Задача разработки (DEV-2.2)*::
Доработка мобильного фронтенда под интеграцию новых визуальных и нейро-компонентов. Внедрение плагина расшифровки полей на уровне приложения (Crypto SDK). Реализация слоя интеграции с локальной шиной для обработки транзакций и создания отложенных заказов в офлайн-режиме.

*Задача тестирования (QA-2.2)*::
Функциональное и регрессионное тестирование карточки товара. Использование mock-профилей и эмуляторов для верификации нечеловеческих способов ввода. Нагрузочное тестирование модуля парсинга JSONB-схем.
