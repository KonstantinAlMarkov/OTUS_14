= Критерии приемки и регламент тестирования

Документ описывает требования к проверке качества (QA) и правила, при выполнении которых задача переводится в статус «Готово».

== Ключевые критерии приемки (Acceptance Criteria)

* [ ] *AC-01 (Отображение)*:: Продукт корректно добавляется в каталог мобильного приложения и отображается на тестовых устройствах.
* [ ] *AC-02 (Безопасность)*:: Поле цены успешно расшифровывается встроенным Crypto SDK на стороне мобильного приложения и выводится в UI в соответствии с выбранной планетой/луной.
* [ ] *AC-03 (Мультикультурность)*:: Переключение интерфейса ввода/вывода под расовые особенности (телепатия, альтернативные экраны) по событию занимает менее 500 мс, не вызывая падения приложения.
* [ ] *AC-04 (Офлайн-режим)*:: При имитации обрыва связи устройство переходит в автономный режим, не зависает и сохраняет доступ к кэшированному списку меню с возможностью создания локального отложенного заказа.
* [ ] *AC-05 (Транзакции)*:: После проведения тестовой онлайн-оплаты в топик `order-events` успешно публикуется валидное асинхронное сообщение `Order_Paid` со структурой векторного времени (Vector Clocks).

== Профиль тестирования расовых интерфейсов (Mock Emulation)

Для снижения стоимости тестирования (митигация риска удорожания QA) инженер по тестированию обязан использовать программные mock-профили:

`MOCK_RACE_TELEPATH_INPUT`::
Эмуляция входящих нейро-пакетов без физического касания экрана.

`MOCK_RACE_MULTIHAND_UI`::
Проверка корректности расположения кнопок при одновременном многоточечном вводе (Multi-touch).
