== Назначение 
МкС предназначен для выполнения следующих функций:
* Оркестрация пошагового процесса согласования новинки (бизнес-контур доски Kanban).
* Строгая проверка входящих сложноструктурированных JSONB-пакетов перед записью.
* Сохранение мастер-данных состава, ингредиентов и КБЖУ в центральную базу данных.
* Публикация асинхронного события `RecipeCertified` со структурой векторного времени для репликации на удаленные точки сети.

== Архитектурная схема работы сервиса
Микросервис развернут в центральном бэк-офисе Земли (SOA-контур). Принимает запросы от веб-портала аналитиков через API Gateway, где OPA Engine проверяет права доступа (RBAC). Для защиты данных от порчи и инъекций в нечеловеческих UI-пакетах, сервис пропускает объект через встроенную библиотеку `json_val_r` перед фиксацией в хранилище.

== Детальное описание методов сервиса

== CertifyProductRecipe
* *Название метода*: CertifyProductRecipe
* *Путь метода*: `/api/v1/recipes/certify`
* *Тип взаимодействия*: _синхронный_
* *Тип операции*: POST
* *Тип входящего сообщения*: http запрос, Content-Type: application/json
* *Тип исходящего сообщения*: http ответ, Content-Type: application/json
* *Влияние на группы продуктов*: не применимо
* *Описание очередей MQ*: топик `recipe-certified` (Earth Kafka Broker)
* *Бизнес-объект*: Технологическая карта продукта (`Recipe_Object`)

=== Краткое описание метода
Метод фиксирует финальные согласованные требования к новинке от всех департаментов, проверяет структуру JSONB-схемы и инициирует асинхронную рассылку мастер-данных по удаленным планетам.

=== Диаграмма работы метода
Диаграмма последовательности шагов оркестрации: link:diagrams/sequence.puml[Диаграмма последовательности метода]

=== Алгоритм работы метода
. *Формирование и отправка запроса*
.. Лид бизнес-анализа или технолог через веб-портал отправляет финальный паспорт продукта в метод `/recipes/certify`.
.. Модуль `json_val_r` выполняет строгую валидацию входящего тела запроса на соответствие JSON-схеме (проверка состава, структуры КБЖУ и расовых полей ввода).
... Если валидация неуспешна, сценарий прерывается с ошибкой HTTP code = 400 (Bad Request), процесс останавливается.
. *Обработка результата операции*
.. Сервис фиксирует изменения в `Recipe DB (PostgreSQL)`.
.. В топик `recipe-certified` центрального брокера публикуется событие `RecipeCertified`, содержащее паспорт продукта и структуру метаданных векторного времени (`Vector Clock`).
- Если при обращении к СУБД или брокеру произошел аппаратный сбой, выполнение сценария завершается с HTTP code = 500.

== Нефункциональные требования

=== Политики обеспечения безопасности и целостности
Внедрение расширения `JSON Schema Validator` на уровне репозитория хранения. Гарантирует защиту PostgreSQL от деструктивных инъекций в случае компрометации API-слоя.

=== Аутентификация и авторизация
. Необходимо использовать аутентификацию и авторизацию на базе Open Policy Agent (OPA) на периметре API Gateway для изоляции промышленного контура.

=== Защищаемые объекты
